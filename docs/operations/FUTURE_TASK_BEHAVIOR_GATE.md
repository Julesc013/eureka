# Future Task Behavior Gate

Future product-scoped tasks must prove runtime behavior. Contracts, policies, examples, validators, and audit reports alone are insufficient.

Definition of done for applicable product tasks includes command execution, persistent state where applicable, tests, negative tests, audit evidence, local workbench proof where applicable, no forbidden side effects, and clean rerun/resume behavior.

If a task is too large to prove, split it before generating scaffolding. Warning debt must be disposed before advancing.
