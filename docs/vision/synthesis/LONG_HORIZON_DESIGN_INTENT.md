# Long-Horizon Design Intent

The long horizon is a cross-era, cross-domain resolution system. Eureka should preserve identity, provenance, evidence, review state, policy posture, compatibility, absence, and unresolved needs across many clients and many source families.

## Domain breadth

The archive begins with old software/archive search, but it expands toward a universal artefact resolver. Future domain packs may cover drivers, manuals, packages, source releases, scanned documents, media lineage, format history, compatibility records, provenance-obscured cultural objects, and hidden members inside containers.

## Interface breadth

Eureka should expose the same semantic product language through many representations: JSON, text, terminal, old-browser HTML, classic search, rich web, snapshots, relay, native cards, and future agent contexts. This is not “same UI code everywhere”; it is same contracts, same semantics, same policy decisions, different renderers.

## Discovery breadth

SCOUT should become relation-guided discovery, not popularity optimization. F extraction should become safe hidden-member discovery, not a generic archive tool. Source expansion should add many source adapters only after one run kernel, one scheduler, one lane projector, one review bridge, and one policy gate exist.

## Product ecosystem

Public hosting, native clients, mobile clients, marketplace/app-manager behavior, install/emulation handoff, public contribution intake, and preservation/time-machine actions are future ambitions. They require policy, security, rights/takedown, malware/risk handling, quarantine, signatures, trust/reputation, rollback, monitoring, and operations before they are product claims.
