# Current Project Reality

## Status classification

This corpus is an archive-derived synthesis. It does not include the live repository. Therefore it can identify strong conversation-level doctrine, repeated decisions, and reported milestones, but it cannot verify current implementation truth.

## Safe to rely on as corpus-level doctrine

The following are stable across multiple packages:

- Eureka is an evidence-first temporal artefact/object resolver, not merely a search engine.
- Review is the truth boundary; candidates and metadata do not become truth automatically.
- Public search must remain bounded and should not perform arbitrary live fanout.
- Dry-runs and fixtures prove shape and behavior but are not authoritative stores.
- Local-first Workbench/product proof is preferred over more static planning.
- The IA metadata pilot is the first source-family pattern, but not full IA integration.
- SYN is evaluation pressure, not evidence.
- DOMAIN, SCOUT, F extraction, native clients, marketplace behavior, and public hosting are later/gated.
- AIDE/Codex task packets are control metadata, not product truth.
- Current repo authority outranks chat memory and generated archive reports.

## Reported but requiring verification

The zips report that Local Appliance, HUNT, PLAY, and an IA metadata pilot had been completed or close to complete through specific local proofs. They also report branch, queue, P-number, and snapshot states at different times. These statements must be checked against the current repository, branch status, queue, and build artifacts before any implementation plan treats them as fact.

## Explicit non-claims

The corpus does not establish that Eureka can currently:

- search all of Archive.org from a browser;
- crawl remote sources broadly;
- download files or run installers;
- unpack arbitrary archives or index hidden package members;
- perform Wayback replay;
- host a public production service;
- support accounts, uploads, telemetry, public contribution intake, marketplace/install behavior, or native app managers;
- use AI output as verified truth.

## Current practical reality

The strongest reality is not “the product is done.” It is that the project has a coherent architectural doctrine and enough local/source/evidence/review planning material to stop generating broad handoff prompts and begin consolidating into verifiable kernels, contracts, Workbench flows, and source lanes.
