# Risk Register

| Risk | Severity | Mitigation |
|---|---|---|
| Archive claims treated as current repo truth | high | Require repo verification and authority labels before promotion. |
| Evidence-card/machine-report style dominates the book | high | Use synthesis prose first; keep block IDs in references, not reading flow. |
| Public search overclaims source coverage | high | Keep limitations, coverage, known-need, and bounded-absence pages explicit. |
| IA metadata mistaken for verified artifacts | high | Preserve source observation/candidate/review/index layers. |
| Broad source expansion creates one-off scripts | high | Build one ResolutionRunKernel, WorkUnit scheduler, lane projector, source adapter seam, and review bridge. |
| UI forks create separate truths | high | Add TSIS contracts, SurfaceKernel, renderer contracts, and semantic parity tests. |
| Generated state becomes stale | medium | Trust current repo and live branch/status checks over generated reports. |
| Full tests waste AI time | medium | Externalize full discovery; consume compact summaries. |
| Old-browser/native/agent surfaces weaken policy | medium | Render only policy-approved actions; enforce legacy/auth isolation. |
| Long-horizon ambitions crowd near-term proof | medium | Sequence: closeout → contracts → run/workbench proof → source expansion → public/native/ecosystem. |
