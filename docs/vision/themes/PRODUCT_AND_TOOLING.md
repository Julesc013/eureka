# Product and Tooling

The strongest product surface is the Workbench: an internal/operator superset of the final product, not a throwaway admin page. Public web, API, CLI/TUI, snapshot/relay, native, and mobile should be restricted projections of the same kernel and packets.

## Key synthesis

The IA metadata pilot is treated as the first source-family proof, but only metadata/source-cache/evidence/candidate/review/index proof. It is not full Archive.org crawling, downloads, file fetching, Wayback replay, or hidden-member extraction.

## Unresolved questions

Open questions include whether IA is promoted from dev to main, what Workbench routes/view contracts are canonical, when operator writes can be enabled, and how live IA metadata becomes browser-visible without coupling the page to IA scripts.

## Contradictions or drift

The product drift is from public-alpha optimism toward local product proof. The corpus repeatedly rejects launching from an empty shell and treats reviewed-corpus growth as the machine.

## Implications for future work

Near-term tooling should focus on source/snapshot closeout, run-kernel/workbench integration, Search Interaction Contract, result lanes/events, IA-HUNT bridge, review/promote UI, and local apply gates.
