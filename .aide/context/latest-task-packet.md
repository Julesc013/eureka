EUREKA-AIDE-GOLDEN-01 - Add Eureka-specific AIDE golden tasks

## GOAL

Add a small Eureka-specific AIDE Lite golden task set that checks compact packet
readiness against Eureka boundaries and evidence expectations, without changing
Eureka product behavior.

aliases, so the remaining handover quality gap is that Eureka still relies on
generic imported AIDE golden tasks. A target-specific golden task pack will make
future compact packets safer before product implementation starts.

## IMPLEMENTATION

- Inspect the existing generic golden tasks and runner behavior first.
- Add one small Eureka-specific golden-task group or catalog entries that check
  compact packet readiness for Eureka boundaries, such as:
  - product paths are not allowed unless explicitly scoped;
  - required evidence paths are present for queue tasks;
  - packets cite Eureka memory/context refs instead of long chat history.
- Keep checks deterministic and repo-local.
- Do not add provider/model/network calls, exact tokenizers, LLM judges, broad
  product audits, or product feature implementation.
- Preserve existing generic golden tasks.
